# LLM+Skill 驱动的“项目、团队、人员”三位一体架构方案

在传统的研发管理中，**项目（做什么）**、**团队（谁来协作）**和**人员（谁来执行）**三者往往处于“信息孤岛”状态：
- 项目需求用的是“业务和功能语言”（如：实现一个高并发的分销系统）。
- 团队管理用的是“编制和组织语言”（如：后端组、前端组、HC 预算）。
- 人员能力用的是“简历和主观语言”（如：精通 Java、熟悉 Spring）。

这种方言的不统一，导致了**资源错配**、**技术单点故障（Bus Factor 过低）**以及**开发者个人成长与项目脱节**。

通过引入 **LLM + Skill（动态技能图谱）**，我们可以将 Skill 作为“统一货币”，构建一套**“三位一体、动态闭环”**的智能架构。

---

## 1. 架构核心理念：Skill 作为“统一货币”

我们将所有实体（项目、团队、人员）全部数字化，映射到同一个**动态技能图谱 (Dynamic Skills Graph)** 中。LLM 在其中扮演**“语义翻译官”**和**“动态画像师”**的角色。

```
                  ┌───────────────────────┐
                  │   动态技能图谱 (Skill) │
                  │  (统一语言/本体知识库)  │
                  └───────────┬───────────┘
         需求提取              │             动态画像
         (Demand)             │             (Supply)
            ┌─────────────────┼─────────────────┐
            ▼                                   ▼
┌───────────────────────┐           ┌───────────────────────┐
│     项目 (Project)     │           │     人员 (People)     │
│  (任务/代码/交付物)   │           │  (代码/提交/成长意愿)  │
└───────────┬───────────┘           └───────────┬───────────┘
            │                                   │
            │           组织架构聚合            │
            └─────────► 团队 (Team) ◄───────────┘
                      (编制/互补/效能)
```

---

## 2. 三位一体的维度建模 (Three-Dimensional Modeling)

### 2.1 人员维度 (People) ── 技能供给画像 (Capability Supply)
不再依赖静态的“简历”，而是通过 LLM 实时分析开发者的**实际工程行为**，生成动态的 Skill 画像。

- **LLM 数据输入源**：
  - **Git 提交 (Commit Diffs)**：分析其编写的代码涉及哪些技术栈、复杂算法、系统调用。
  - **PR 评审意见 (Code Review Comments)**：分析其给他人提出的意见。提问深度的代码（如并发、内存泄漏），代表其在该领域的认知水平高于普通编码。
  - **个人发展意愿 (Career Goals)**：开发者自主填写的“希望学习/尝试的技术”。
- **LLM 提取与输出**：
  - **技能雷达图**：不仅有“掌握度”（基于行为频次与复杂度），还有“成长速度”（基于时间序列的斜率）。
  - **角色偏好标签**：如“架构守护者”、“Bug 终结者”、“敏捷交付先锋”。

---

### 2.2 项目维度 (Project) ── 技能需求画像 (Capability Demand)
将项目或具体任务（Jira Ticket / Pull Request）转化为对 Skill 的具体需求。

- **LLM 数据输入源**：
  - **存量代码库 (Codebase)**：LLM 扫描项目结构，识别核心依赖与技术架构（如：Spring Boot + Kafka + Redis）。
  - **需求文档 & 任务单 (PRD / Jira / Linear Tickets)**：LLM 解析任务描述，识别其需要的特定技能。
- **LLM 提取与输出**：
  - **任务技能画像 (Task Skill Profile)**：例如，“任务 #1024 需要：React Hooks 优化（高）、CSS Grid（中）、性能调试（高）”。
  - **项目技术债画像**：识别项目中哪些模块代码质量差、漏洞多，转化为对“重构/安全技能”的紧急需求。

---

### 2.3 团队维度 (Team) ── 组织效能与互补 (Synergy & Structure)
团队不是个人的简单求和，而是基于组织架构和协作网络的**有机聚合体**。

- **LLM 数据输入源**：
  - **组织架构树**：部门 -> 中心 -> 小组 -> 个人。
  - **协作图谱 (Social Graph)**：通过 Git PR 的“指派-评审-合并”链条，分析组内成员的协作紧密度。
- **LLM 提取与输出**：
  - **小组技能矩阵 (Team Skill Matrix)**：聚合组内所有人员的 Skill，展示小组的整体技术储备。
  - **技术单点故障风险 (Bus Factor)**：LLM 自动识别“某个核心模块是否只有 A 懂，其他人都不懂”的风险，发出预警。
  - **团队互补度 (Synergy Index)**：评估团队成员之间技术栈的重合与互补情况，指导梯队建设。

## 3. 三大核心闭环机制 (The Three Loops)

这套架构最强大的地方在于，通过 LLM + Skill 实现了三个层面的**自动闭环和智能调度**：

```
                       【项目 (Project)】
                             ▲   │
                     (C) 承载│   │ (A) 智能
                         评估│   │     派单
                             │   ▼
【团队 (Team)】 ◄───────────────┼───► 【人员 (People)】
                 (B) 梯队补齐
```

### 闭环 A：智能派单与精准评审 (Project ◄──► People)
- **场景**：新来了一个高难度的数据库优化任务，或者提交了一个涉及底层并发的 PR。
- **机制**：
  1. LLM 解析该任务/PR，识别出需要的核心 Skill 是 `MySQL Index Tuning` 和 `Java Concurrency`。
  2. 系统检索候选人库，通过 LLM 匹配算法，找到当前 Skill 匹配度最高、且有空闲带宽（或正在关注该领域）的开发者。
  3. **自动指派**：自动将该任务指派给他，或者指定他作为该 PR 的 Reviewer。
- **价值**：研发主管不再需要凭直觉分工，PR 评审也更有针对性。

### 闭环 B：团队梯队与人才补齐 (Team ◄──► People)
- **场景**：团队要承接云原生转型，但不知道技术储备是否足够。
- **机制**：
  1. 团队能力矩阵聚合后，LLM 发现该小组的 `Kubernetes` 和 `Docker` 技能平均分极低（技术短板）。
  2. **智能培训推荐**：LLM 结合组内成员的“个人发展意愿”，发现组员小明想学云原生。系统自动将小明与该技术短板绑定，推荐相关的内部项目或培训课程。
  3. **招聘决策辅助**：如果组内没人想学或来不及学，系统自动向 HR 输出招聘画像：“我们需要一个 3 年以上经验、具备 K8s 实战经验的后端专家”。
- **价值**：组织发展（OD）与个人成长（L&D）完美对齐。

### 闭环 C：项目规划与承载力评估 (Project ◄──► Team)
- **场景**：业务部门规划了下个季度的 5 个大项目，技术总监需要评估能不能接。
- **机制**：
  1. LLM 解析这 5 个项目的 PRD，输出整体的“项目群技能需求”。
  2. 比对相关团队的“团队技能矩阵”与“当前带宽（Cycle Time）”。
  3. **风险预测**：LLM 输出评估报告：“团队 A 缺乏足够的 Golang 专家，承接项目 X 的风险为高（预计延期 2 周）；建议将项目 Y 调拨给技能更匹配的团队 B”。
- **价值**：从源头规避因技能不匹配导致的交付延期。

## 4. 技术实现架构 (Technical Implementation)

要落地这套三位一体系统，核心在于构建一个 **“Skill Ontology（技能本体库）”** 和 **“AI Extraction Pipeline（AI 提取流水线）”**：

1.  **统一技能本体库 (Skill Ontology)**：
    - 不能只做简单的关键词匹配。需要利用 LLM 构建一个包含层级和关联关系的技能图谱（例如：`React` ──属于──► `Frontend` ──关联──► `Next.js`、`Webpack`）。
2.  **多源异构数据解析流水线 (LLM Pipeline)**：
    - **Jira/PRD 需求** ──► [LLM 语义提取] ──► 技能需求 (Demand Tag)
    - **Git Diff/PR 评语** ──► [LLM 行为分析] ──► 技能供给 (Supply Tag)
3.  **图计算与聚合引擎**：
    - 利用图数据库（如 Neo4j）存储 `People -[has_skill]-> Skill` 和 `Project -[requires_skill]-> Skill` 的关系。
    - 利用加权聚合算法，沿着组织架构树（Team Tree）向上汇总，生成团队的实时效能看板。
