# 开发者能力实测评估模块 详细设计文档

> 目标：文档细到代理可照做、无需追问。写完后派发代理时让其"先读本文档，按第 8 节开发顺序逐条实现"。

## 0. 设计目标

### 现状痛点
- `capability_roles` / `capability_standards`（12 职级阈值）已后端化，但**从未被真实评估使用**。
- 开发者详情页（`frontend/app/developers/[id]/page.tsx`）的"能力雷达 + 达标率 + 维度明细"全部来自 seed 的 mock 数据（`backend/app/seed.py` 的 `_DEV_DETAILS` 里硬编码 `capability` JSON 字段），`detail.capability` 与 `detail.roleStandard` 都是假数据。
- 用户要求打通"**规则即资产**"核心闭环：按角色取 Skill Group 规则 → 对开发者在真实仓库的代码贡献做 LLM 实测打分 → 与能力标准阈值对比 → 得出达标职级与差距。

### 一句话定位
新增**开发者能力实测评估**链路：选择真实 git 仓库 + git 作者 → 按作者采样其代码 → LLM 依据该开发者角色的 Skill Group 规则逐维度打分（0-100）→ 与 `capability_standards` 各职级阈值对比 → 判定达标职级 + 差距清单，落库并展示在开发者详情页。

### 数据流（ASCII）
```
[开发者详情页] 选择仓库+git作者 → POST /developers/{did}/evaluations
        ↓ (后台线程)
git_collect: 按 author 过滤提交 → 采样该作者代码文件
        ↓
LLM (chat_json): 注入 [角色维度] + [Skill Group 规则] + [代码样本]
        ↓ scores: {dimension: 0-100} + evidence + summary
后端判定: scores vs capability_standards 12 职级阈值 → achieved_level + gaps
        ↓
developer_evaluations 表落库 → GET 详情页轮询展示
```

## 1. 数据模型设计

### 新表：developer_evaluations（1 张）

```python
class DeveloperEvaluation(Base):
    """开发者能力实测评估记录：一次评估 = 一个 git 作者在某仓库的代码贡献打分"""
    __tablename__ = "developer_evaluations"

    id = Column(String, primary_key=True)          # deval-xxx (uuid4().hex[:12])
    developer_id = Column(String, ForeignKey("developers.id"), nullable=False)
    role_key = Column(String, nullable=False)      # frontend|backend|devops|algorithm|qa（取 developer.role_type）
    skill_group_id = Column(String, ForeignKey("skill_groups.id"), nullable=True)  # 评估用的规则组
    repo_path = Column(String, nullable=False)     # 评估数据源（真实 git 仓库绝对路径）
    git_author = Column(String, nullable=False)    # git 作者名（git log --format=%an）
    scores = Column(JSON, default=dict)            # {"code_quality": 85, "architecture": 78, ...} 实测分
    evidence = Column(JSON, default=list)          # [{"dimension","summary","rules":[{"rule","hit","note"}]}]
    achieved_level = Column(String, nullable=True) # 达标职级（D1-G3），所有维度>=阈值才算达标；无则 NULL
    best_level = Column(String, nullable=True)     # 参考职级（分数最接近的职级，展示用）
    gaps = Column(JSON, default=list)              # [{"dimension","current","target","gap"}] 与达标职级或最近职级的差距
    summary = Column(Text, default="")             # LLM 整体评价（一段话）
    status = Column(String, default="running")     # running|completed|failed
    error = Column(Text, default="")               # 失败原因（status=failed 时）
    created_at = Column(String)                    # ISO datetime
    updated_at = Column(String)
```

### 存量表
- **capability_roles**：读取 `dimensions`（角色维度集）、`skill_group_id`（关联规则组）——**不改结构**。
- **capability_standards**：读取 12 职级阈值 `{role_id, level, thresholds}` 用于达标判定——**不改结构**。
- **repositories**：`path` 字段已存真实仓库路径（如 `/home/tutuos/CodeLab/calendar-task-manager`），评估数据源从这里选——**不改结构**。
- **skill_groups / skills**：读取规则（复用 analyzer.py 的 `_load_group_rules`）——**不改结构**。

## 2. API 设计

新建 `backend/app/routers/evaluations.py`，在 `main.py` 注册（`app.include_router(evaluations.router, prefix="/api/v1")`）。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/developers/{did}/evaluations` | 触发一次评估（后台线程），立即返回 `{id, status:"queued"}` |
| GET | `/api/v1/developers/{did}/evaluations` | 该开发者全部评估记录（按 created_at 倒序） |
| GET | `/api/v1/developers/{did}/evaluations/latest` | 最近一次评估（详情页轮询用） |
| GET | `/api/v1/developers/{did}/evaluations/{eid}` | 单条评估详情 |
| GET | `/api/v1/git-authors?repo_path=...` | 列出某仓库的全部 git 作者（前端下拉数据源） |

### POST /developers/{did}/evaluations
请求体：
```json
{
  "repo_path": "/home/tutuos/CodeLab/calendar-task-manager",
  "git_author": "Tutuhuang",
  "role_key": "backend",
  "skill_group_id": "skg-seed-java"
}
```
- `role_key` / `skill_group_id` 可省略：缺省时取 `developer.role_type` 和该角色的 `capability_roles.skill_group_id`；角色未关联组则只用内置 prompt（无规则注入，仍可打分）。
- 响应 202：`{"id":"deval-xxx","status":"queued"}`

### GET /developers/{did}/evaluations/latest
响应字段（完整）：
```json
{
  "id": "deval-xxx", "developerId": "d1", "roleKey": "backend",
  "skillGroupId": "skg-seed-java", "repoPath": "...", "gitAuthor": "Tutuhuang",
  "scores": {"code_quality": 85, "architecture": 78, "stability": 82, "efficiency": 80,
             "collaboration": 88, "security_aware": 74, "test_coverage": 70, "growth_velocity": 76},
  "evidence": [{"dimension":"code_quality","summary":"...","rules":[{"rule":"禁止硬编码密钥","hit":true,"note":"..."}]}],
  "achievedLevel": "F2", "bestLevel": "F2",
  "gaps": [{"dimension":"security_aware","current":74,"target":80,"gap":6}],
  "summary": "整体评价...", "status": "completed", "error": "",
  "createdAt": "2026-08-02T...", "updatedAt": "..."
}
```
- `scores` 为空字典且 `status=running` → 前端显示"评估中"。
- `status=failed` → 前端显示 `error`。

### 判定规则（后端纯逻辑，不依赖 LLM）
1. 取该角色 `capability_standards` 全部 12 个职级的 thresholds（缺省用 capability.py 的 `default_thresholds(role_key, level)` 兜底）。
2. **达标职级**：按 ALL_LEVELS 顺序（D3→G1，从高到低）逐个检查 `scores[dim] >= thresholds[dim]` 对所有角色维度成立；第一个全达标的职级 = `achieved_level`；都不达标 → `achieved_level=None`。
3. **参考职级**：对每个职级算 `scores` 与阈值差的平方和（欧氏距离），距离最小的 = `best_level`。
4. **gaps**：取 `best_level`（若 achieved_level 存在则取 achieved_level 的下一级）作为目标，`target = thresholds[dim]`，`gap = target - current`（仅 gap > 0 的维度列出）。

## 3. 核心改造方案

### 3.1 git_collect.py 新增按作者采样函数

```python
def collect_author_code(repo_path: str, author: str, max_files: int = 10, max_bytes: int = 6000) -> dict:
    """按 git 作者过滤提交，采样该作者修改过的代码文件内容。
    返回 {"author": author, "commits": N, "files": ["src/a.go", ...], "samples": [{"path","content"}], "totalCommits": N}
    实现要点：
    1. files = `git log --author="<author>" --name-only --pretty=format: -- <repo>` 去重（过滤非代码扩展名）
    2. 若 files 为空 → 返回 {"author":..., "commits":0, "files":[], "samples":[]}（上层提示作者无提交）
    3. 按扩展名权重排序（作者 langs 里的主语言优先），取前 max_files 个文件
    4. 读文件内容（read_text errors="ignore"，截断 max_bytes）
    5. commits = `git rev-list --count --author="<author>" HEAD`
    """
```
- 新增模块级常量 `CODE_EXT` 已存在（文件顶部），直接复用。
- **注意**：`git log --author` 匹配的是提交者名字字符串，支持中文（如 "Tutuhuang" / "dt_flys"）。

### 3.2 新建 backend/app/evaluation.py（评估引擎，模式对齐 analyzer.py）

```python
"""开发者能力实测评估引擎：git 作者代码采样 → LLM 按角色维度+Skill 规则打分 → 职级判定"""
from .llm import chat_json
from . import models
from .capability import default_thresholds, ALL_LEVELS, DIMENSION_LABELS

def evaluate_developer(db, evaluation_id: str) -> None:
    """后台线程入口：按 developer_evaluations 记录执行完整评估"""
    # 1. 读 evaluation 记录 + developer + capability_role
    # 2. git 采样：collect_author_code(repo_path, git_author)
    #    - commits == 0 → status=failed, error="git 作者无提交记录"
    # 3. 加载规则组：复用 analyzer._load_group_rules(db, skill_group_id)（导入 analyzer 的函数）
    # 4. LLM 打分：build_evaluation_prompt()（见第 4 节）→ chat_json(..., 8000)
    #    - scores 缺失的维度用 60 兜底；非数字强制 int；范围 clamp 0-100
    # 5. 职级判定：_judge_level(scores, role_key, db) → achieved_level/best_level/gaps
    # 6. 写回 evaluation 记录 status=completed + scores/evidence/achievedLevel/gaps/summary
    # 异常 → status=failed + error=str(e)[:200]
```

### 3.3 达标判定函数（evaluation.py 内）

```python
def _judge_level(scores: dict, role_key: str, db) -> tuple[str | None, str, list[dict]]:
    """返回 (achieved_level, best_level, gaps)"""
    # thresholds_by_level: 从 capability_standards 读（role 对应行），缺省 default_thresholds(role_key, level)
    # achieved: 从 D3 往 G1 扫，全部维度 score >= threshold → achieved
    # best: 距离最小（sum((s - t)^2)）
    # gaps: 以 best_level 阈值做目标，gap>0 的维度
```

## 4. LLM Prompt 模板

### prompt（中文，注入角色维度 + Skill 规则 + 代码样本）

```
你是资深{role_name}面试官，依据以下评估维度与编码规范规则，对一名开发者的真实代码贡献进行能力评分。

【评估维度】（每维 0-100 整数分）
- code_quality（代码质量）
- architecture（架构能力）
- stability（稳定性）
- efficiency（交付效率）
- collaboration（协作能力）
- security_aware（安全意识）
- test_coverage（测试覆盖）
- growth_velocity（成长速度）

【编码规范规则】（必须逐条检查代码是否命中）
- [high] 禁止硬编码密钥：不得在代码中明文出现密码/Token/密钥
- [medium] 日志规范：生产日志需分级且不泄露敏感信息
- ...

【该开发者代码样本】（git 作者 {git_author}，共 {commits} 次提交，采样 {n} 个文件）
--- src/auth.go ---
<code>
...

输出严格 JSON（不要 markdown 代码块、不要解释）：
{"scores":{"code_quality":0,"architecture":0,"stability":0,"efficiency":0,"collaboration":0,"security_aware":0,"test_coverage":0,"growth_velocity":0},
 "evidence":[{"dimension":"code_quality","summary":"打分依据一句话","rules":[{"rule":"规则名","hit":true,"note":"命中说明"}]}],
 "summary":"整体评价 2-3 句话"}

要求：
- scores 每维必须是纯数字 0-100，禁止描述文字
- evidence 必须覆盖每个维度（数组长度 == 维度数）
- rules 里每条规则都要出现（hit 表示代码中是否命中该规则风险）
- 只输出 JSON 对象
```

> 角色维度列表从 `capability_roles.dimensions` 动态生成（role_key 对应的 ROLE_DIMENSIONS 兜底）；规则列表从 `_load_group_rules` 的 skills 生成（`- [severity] name：rule_content`），无规则组时省略【编码规范规则】段。
> DIMENSION_LABELS 从 capability.py 导入生成中文标签。

### 容错解析
- `scores` 非 dict → 全维度 60 兜底；维度值非 int/超范围 → `_clamp(int(v), 0, 100)`。
- `evidence` 非 list → 空列表兜底。
- `summary` 非 str → 截断为 ""。

### 5.3 关键交互（步骤化）
1. 页面加载：`getLatestDeveloperEvaluation(did)`，若有 completed 记录 → 展示结果卡片；否则显示"尚未实测评估"占位。
2. 数据源选择：输入框填仓库路径（默认 `detail` 关联项目仓库 path，从 `getRepos()` 过滤 path 非空）→ 失焦后 `getGitAuthors(repoPath)` 填充作者下拉。
3. 点"开始实测评估" → `triggerDeveloperEvaluation(did, {repo_path, git_author, role_key: detail.roleType})` → 状态"评估中…"。
4. 轮询 `getLatestDeveloperEvaluation(did)` 每 3 秒一次，`status==='completed'|'failed'` 停止（最多 30 次）。
5. 结果展示（completed）：
   - 顶部行：`achievedLevel` Badge（达标职级，无则"未达任何职级"）+ `bestLevel` 参考 + `gitAuthor` / `repoPath` 来源 + `createdAt`。
   - `CapabilityRadar`：series = [{name:'实测', data: scores}, {name:`${achievedLevel||bestLevel} 标准`, data: 该职级阈值}]（阈值从 `/capability-standards/{role_key}` 接口拿或由后端 gaps 附带 target）。
   - 维度明细网格（复用页面现有 calcPassRate 风格）：每维显示 实测/标准 + ✓达标或差 N 分。
   - gaps 列表：红色列出未达标维度与差距。
   - evidence 折叠区：每条 dimension 的 summary + rules（hit=true 红色标"命中"，false 绿色"未命中"）。
   - summary 段落展示。
6. `status==='failed'` → 红色错误提示 + error 文本，按钮可重试。
