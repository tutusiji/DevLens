# DevLens 项目环境配置盘点模块详细设计文档

## 1. 定位与目标

对每个已接入项目进行**配置文件盘点**：扫描仓库内的 `.env` / `application*.yml` / `application*.properties` / `bootstrap*.yml` / `docker-compose*.yml` / `values*.yaml` 等配置文件，解析出项目用到的所有**工具/中间件连接配置**（数据库、Redis、Nacos、消息队列、搜索引擎等），按**环境**（开发/测试/生产/灰度）归类展示，并记录每条配置的**来源文件**与**扫描更新时间**。

核心原则：
- **数据不是死的**：每次扫描生成新快照，展示最新结果 + 最近扫描时间。
- **来源可溯**：每条配置必须标注来源文件（相对路径）+ 扫描时间。
- **双模式重扫**：「按此历史更新」（仅重读上次发现的文件，增量）与「全量再次更新」（重新发现全仓库配置文件，全量）。
- **密码脱敏**：账号密码不存明文，展示脱敏值。

## 2. 数据模型（backend/app/models.py 新增 2 张表）

### 2.1 config_scans（扫描批次）

```python
class ConfigScan(Base):
    __tablename__ = "config_scans"
    id = Column(String, primary_key=True)              # "cs-" + uuid 短码
    project_id = Column(String, ForeignKey("projects.id"))
    mode = Column(String, default="full")              # full=全量 | incremental=按历史更新
    status = Column(String, default="running")         # running | completed | failed
    file_count = Column(Integer, default=0)            # 本次扫描读取的文件数
    item_count = Column(Integer, default=0)            # 本次扫描解析出的配置项数
    started_at = Column(String)                        # ISO 时间
    finished_at = Column(String)
    message = Column(Text)                             # 失败原因或摘要
```

### 2.2 config_items（配置项）

```python
class ConfigItem(Base):
    __tablename__ = "config_items"
    id = Column(String, primary_key=True)              # "ci-" + uuid 短码
    project_id = Column(String, ForeignKey("projects.id"))
    scan_id = Column(String, ForeignKey("config_scans.id"))
    tool_type = Column(String)     # mysql|postgresql|redis|nacos|kafka|rabbitmq|rocketmq|elasticsearch|mongo|mq|other
    env = Column(String)           # dev|test|prod|gray|local|unknown
    host = Column(String)
    port = Column(String)
    username = Column(String)
    password_masked = Column(String)   # 脱敏密码（如 p***d / ****）——绝不存明文
    database = Column(String)          # 库名 / db index
    source_file = Column(String)       # 来源文件相对路径（如 .env.prod、config/application-prod.yml）
    raw_key = Column(String)           # 原始配置键路径（如 spring.datasource.url、DB_HOST）
    line_no = Column(Integer, nullable=True)
    detail = Column(JSON)              # 附加信息：namespace/group/服务名等
    first_seen_at = Column(String)
    updated_at = Column(String)
    fingerprint = Column(String)       # 去重指纹（tool+env+host+port+db+source_file 哈希）
```

查询策略：**只展示每个 project 最新一次 completed 扫描的 config_items**（按 scan_id 过滤）。

## 3. 配置文件发现规则（config_scanner.py）

### 3.1 文件匹配模式（相对仓库根，排除 .git/node_modules/.next/target/dist 等）

| 模式 | 说明 |
| --- | --- |
| `.env`, `.env.*` | 环境变量文件（.env.dev/.env.prod/.env.gray 等） |
| `application*.yml`, `application*.yaml`, `application*.properties` | Spring Boot 配置 |
| `bootstrap*.yml`, `bootstrap*.yaml` | Spring Cloud / Nacos 引导配置 |
| `docker-compose*.yml`, `docker-compose*.yaml` | 容器编排（提取环境变量与服务） |
| `values*.yaml`, `values*.yml` | Helm values |
| `config/**/*.yml`, `config/**/*.yaml`, `config/**/*.properties` | 常见配置目录 |
| `*.conf` | nginx 等（proxy_pass 可提取上游 host:port） |

实现：`find_config_files(repo_path: str) -> list[str]`，用 `os.walk` + 过滤规则，返回相对路径列表。

### 3.2 环境识别（从文件名/键前缀/目录推断）

| 信号 | 环境 |
| --- | --- |
| 文件名含 `.prod` / `-prod` / `.production` | prod |
| 文件名含 `.gray` / `-gray` / `.canary` | gray |
| 文件名含 `.test` / `-test` | test |
| 文件名含 `.dev` / `-dev` / `.development` / 无后缀 `.env` | dev |
| 文件名含 `.local` / `.docker` | local |
| 键前缀 `PROD_` / 目录 `config/prod/` | prod |
| 键前缀 `TEST_` / 目录 `config/test/` | test |
| 其余 | unknown |

实现：`infer_env(file_path: str, key: str = "") -> str`，先文件后键，返回上面枚举。

### 3.3 解析器（按文件类型分发）

- `parse_env_file(content) -> list[dict]`：KEY=VALUE 行解析（忽略注释/空行，支持 `export ` 前缀，支持引号剥离）
- `parse_properties(content) -> list[dict]`：`key=value`（Java properties，支持 `:` 分隔）
- `parse_yaml(content) -> list[dict]`：用 PyYAML（safe_load），输出扁平化 `a.b.c: value` 键路径列表
- `parse_docker_compose(content) -> list[dict]`：YAML 解析，提取每个 service 的 `environment`（键值或列表）与 `image`，键路径形如 `services.postgres.environment.POSTGRES_PASSWORD`

### 3.4 工具类型与连接信息提取（核心规则）

对每个 (file_path, key, value) 组合执行：

**A. URL 模式（值本身是连接串）**
| 正则模式 | tool_type | 提取 |
| --- | --- | --- |
| `jdbc:(mysql\|postgresql)://user:pass@host:port/db` | mysql/postgresql | host/port/user/pass/db |
| `(mysql\|postgresql)://user:pass@host:port/db` | mysql/postgresql | 同上 |
| `redis://:pass@host:port/db` 或 `redis://user:pass@host:port/db` | redis | host/port/user/pass/db |
| `mongodb://user:pass@host:port/db` | mongo | host/port/user/pass/db |
| `(kafka\|rabbitmq\|amqp)://user:pass@host:port` | kafka/rabbitmq | host/port/user/pass |

**B. 键路径模式（Spring 风格）**
| 键包含 | tool_type | 说明 |
| --- | --- | --- |
| `spring.datasource.url` / `spring.datasource.username/password` | mysql/postgresql（按 url 里 jdbc 判断） | 组合同 host:port 的 user/pass |
| `spring.redis.host/port/password/database` | redis | 组合 |
| `spring.cloud.nacos.server-addr` / `nacos.server-addr` | nacos | host:port；`spring.cloud.nacos.username/password` 组合 |
| `spring.kafka.bootstrap-servers` | kafka | host:port 列表取第一个 |
| `spring.elasticsearch.uris` / `elasticsearch.host` | elasticsearch | 组合 |

**C. 通用键名模式（.env / docker-compose）**
| 键（大写归一化） | tool_type | 说明 |
| --- | --- | --- |
| `*_DB_HOST` + `*_DB_PORT` + `*_DB_USER` + `*_DB_PASSWORD`（或 MYSQL_/POSTGRES_ 前缀） | mysql/postgresql | 按前缀 mongo→mongo，redis→redis，默认 mysql |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` / `REDIS_URL` | redis | |
| `NACOS_SERVER_ADDR` / `NACOS_HOST` / `NACOS_USERNAME` / `NACOS_PASSWORD` | nacos | |
| `DATABASE_URL`（postgresql:// 或 mysql:// 前缀） | postgresql/mysql | URL 解析 |
| `KAFKA_BOOTSTRAP_SERVERS` / `RABBITMQ_HOST` | kafka/rabbitmq | |
| docker-compose `services.<name>.environment.POSTGRES_PASSWORD` 等 | 按服务名/键推断 | |

**D. 组合策略**：同一 source_file + env + host:port + tool_type 的 username/password 从邻近键合并（如 `DB_USER` 与 `DB_PASSWORD` 相邻行合并为一条配置项）。

### 3.5 密码脱敏

`mask_password(pw: str) -> str`：
- 空 → 空串
- 长度 ≤ 2 → `****`
- 否则：`首字符 + '*' * max(2, len-2) + 末字符`（如 `p***d`），中文同样处理；长度 > 8 时中间只保留 3 个星号并追加 `(len=N)` 提示长度。

### 3.6 指纹去重

`fingerprint = sha1(f"{tool_type}|{env}|{host}|{port}|{database}|{source_file}")[:16]`，同一扫描批次内同指纹只保留一条（合并 username/password）。

## 4. 扫描执行器（config_scanner.py）

### 4.1 主函数

```python
def run_config_scan(project_id: str, mode: str = "full", background: bool = False) -> None:
```

- 查询 project 关联的 Repository（`project_id` 匹配，取第一条 path 存在的），repo 不存在或 path 不存在 → scan 标记 failed，message 说明。
- 创建 ConfigScan(status=running, mode=mode, started_at=now)。
- **full 模式**：`find_config_files(repo_path)` 全量发现文件 → 逐文件解析。
- **incremental 模式**：查询该 project 最近一次 completed 扫描的 `source_file` 列表（从上次 config_items 去重取）→ 只重读这些文件（文件已删除则跳过并在 message 记录）。
- 解析结果写入 config_items（全量模式先删除该项目旧的 running 之外的所有 items？——不删历史，只按 scan_id 隔离；**查询永远用最新 completed scan_id**）。
- 更新 ConfigScan(status=completed, file_count, item_count, finished_at)。
- `background=True` 时 `threading.Thread(daemon=True)` 执行（对齐 analyzer.py 模式）。

### 4.2 展示查询

```python
def latest_config_items(db, project_id) -> tuple[list[ConfigItem], ConfigScan | None]:
    # 最新 completed scan
    scan = db.query(ConfigScan).filter_by(project_id=project_id, status="completed").order_by(ConfigScan.started_at.desc()).first()
    items = db.query(ConfigItem).filter_by(project_id=project_id, scan_id=scan.id).all() if scan else []
```

## 10. 注意事项

- PyYAML 需要 import yaml（backend/pyproject.toml 确认已含，没有则添加）。
- docker-compose environment 可能是 map 也可能是 list（`- KEY=VALUE`），两种都要处理。
- URL 中密码含 `@`/`:` 时用 `urllib.parse.urlsplit` 拆解，失败则跳过该条。
- 扫描大仓库时限制单文件大小（>512KB 跳过）与文件总数（>500 个截断并记 message）。
- 密码脱敏是硬要求：**任何路径都不得把明文密码写入数据库或响应**。
