## 0. 设计目标

当前「能力标准管理」页面（`frontend/app/capability-standards/page.tsx`，217 行）**完全依赖前端 mock 数据**（`roleConfigs` / `roleStandards` / `DIMENSION_LABELS` 硬编码在 `frontend/lib/mock-data.ts`），「保存」按钮无任何行为，改完刷新即丢。

本模块把能力标准**后端化持久化**，并打通与 Skill 规则（技术维度）的关联——「某职级达标需要满足哪些 Skill 规则」，强化"规则即资产"壁垒。

**核心能力**：
1. 能力标准 CRUD 持久化（角色 × 职级 × 维度 → 阈值分）
2. 角色配置（5 角色 × 各自维度集）持久化
3. 与 Skill 规则关联：每个角色/职级可绑定 Skill Group 或规则列表（达标依据）
4. 前端改为真实 API + mock 兜底（USE_MOCK 双实现）

## 1. 数据模型设计（2 张新表）

### 1.1 capability_roles（角色配置表）

```python
class CapabilityRole(Base):
    __tablename__ = "capability_roles"
    id = Column(String, primary_key=True)          # cr-frontend / cr-backend / cr-devops / cr-algorithm / cr-qa
    key = Column(String, unique=True, nullable=False)  # frontend|backend|devops|algorithm|qa
    name = Column(String, nullable=False)          # 前端工程师 / 后端工程师 ...
    dimensions = Column(JSON, default=list)        # ["code_quality","architecture",...] 维度 key 列表
    skill_group_id = Column(String, ForeignKey("skill_groups.id"), nullable=True)  # 关联 Skill Group（达标依据）
    enabled = Column(Integer, default=1)
    created_at = Column(String)
    updated_at = Column(String)
```

### 1.2 capability_standards（标准阈值表）

```python
class CapabilityStandard(Base):
    __tablename__ = "capability_standards"
    id = Column(String, primary_key=True)          # cstd-xxx
    role_id = Column(String, ForeignKey("capability_roles.id"))
    level = Column(String, nullable=False)         # D1-D3 / E1-E3 / F1-F3 / G1-G3
    thresholds = Column(JSON, default=dict)        # {"code_quality": 85, "architecture": 80, ...} 各维度阈值
    updated_at = Column(String)
    # 联合唯一：role_id + level
```

> 设计决策：
> - **不做「一条记录一个维度」**（会 5 角色 × 12 职级 × 8 维度 = 480 行），而是**一行 = 角色+职级**，阈值放 JSON 字典——读写简单，与前端 `Record<Level, Record<string, number>>` 结构天然对应。
> - 维度 label 字典（`DIMENSION_LABELS`）也入库？不——它是**展示常量**，放后端 config 常量即可，不进表（避免过度设计）。但为兼容前端修改，通过 `/capability-standards/meta` 接口返回。
> - `LEVEL_BASE` / `DIMENSION_OFFSET` 生成逻辑（mock 里的 getRoleStandard）保留为**默认值生成器**：新角色/新职级无数据时按公式生成默认阈值。

## 2. 默认数据生成逻辑（seed）

mock 里的 `getRoleStandard(role, level)` 公式（LEVEL_BASE + DIMENSION_OFFSET，clamp 0-100）**迁移到后端** `capability.py`：

```python
LEVEL_BASE = {"D1": 88, "D2": 92, "D3": 96, "E1": 72, "E2": 76, "E3": 80,
              "F1": 60, "F2": 64, "F3": 68, "G1": 48, "G2": 52, "G3": 56}
DIMENSION_OFFSET = {"code_quality": 5, "architecture": 0, "stability": 3, "efficiency": 2,
                    "collaboration": 0, "security_aware": 8, "test_coverage": -2, "growth_velocity": -5,
                    "ui_quality": 0, "responsive": -3, "automation": 0, "monitoring": 2, "doc_quality": -5,
                    "modeling": 0, "experiment_efficiency": 3, "test_design": 5, "coverage": 0}
ROLE_DIMENSIONS = {
    "frontend": ["code_quality","architecture","ui_quality","responsive","collaboration","security_aware","test_coverage","growth_velocity"],
    "backend":  ["code_quality","architecture","stability","efficiency","collaboration","security_aware","test_coverage","growth_velocity"],
    "devops":   ["automation","monitoring","stability","efficiency","collaboration","security_aware","doc_quality","growth_velocity"],
    "algorithm":["code_quality","modeling","experiment_efficiency","stability","collaboration","security_aware","test_coverage","growth_velocity"],
    "qa":       ["code_quality","test_design","coverage","stability","collaboration","security_aware","automation","growth_velocity"],
}
DIMENSION_LABELS = {"code_quality":"代码质量","architecture":"架构能力","stability":"稳定性","efficiency":"交付效率",
                    "collaboration":"协作能力","security_aware":"安全意识","test_coverage":"测试覆盖","growth_velocity":"成长速度",
                    "ui_quality":"UI 质量","responsive":"响应式","automation":"自动化","monitoring":"监控",
                    "doc_quality":"文档质量","modeling":"建模能力","experiment_efficiency":"实验效率","test_design":"测试设计","coverage":"覆盖率"}

def default_thresholds(role_key: str, level: str) -> dict[str, int]:
    dims = ROLE_DIMENSIONS.get(role_key, [])
    base = LEVEL_BASE.get(level, 60)
    return {d: max(0, min(100, base + DIMENSION_OFFSET.get(d, 0))) for d in dims}
```

`seed_capability()`：5 角色 × 12 职级全部生成默认阈值入库（仅当 capability_roles 为空时）。

## 3. API 设计

新增 `backend/app/routers/capability.py`，prefix `/api/v1`。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/capability-standards/meta` | 返回元数据：DIMENSION_LABELS、ALL_LEVELS、LEVEL_GROUPS、默认 ROLE_DIMENSIONS |
| GET | `/capability-standards` | 全量标准：`[{roleKey, roleName, dimensions, standards: {level: {dim: val}}}]` |
| GET | `/capability-standards/{role_key}` | 单角色标准（含 skill_group_id 关联信息） |
| PUT | `/capability-standards/{role_key}` | 全量保存单角色（body: `{dimensions, standards, skillGroupId}`）——原子替换该角色的 standards 行 |
| PATCH | `/capability-standards/{role_key}/levels/{level}` | 单职级阈值更新（body: `{thresholds: {dim: val}}`） |
| POST | `/capability-standards/reset` | 重置全部为默认值（按 LEVEL_BASE + DIMENSION_OFFSET 重新生成） |

### 响应结构

```json
// GET /capability-standards
{
  "roles": [
    {
      "roleKey": "backend",
      "roleName": "后端工程师",
      "dimensions": ["code_quality", "architecture", ...],
      "skillGroupId": "skg-seed-java",
      "standards": {
        "E3": {"code_quality": 85, "architecture": 80, ...},
        "F1": {"code_quality": 65, ...}
      }
    }
  ],
  "meta": {
    "dimensionLabels": {"code_quality": "代码质量", ...},
    "allLevels": ["D3","D2","D1","E3","E2","E1","F3","F2","F1","G3","G2","G1"],
    "levelGroups": [{"prefix":"D","label":"稀缺高阶","range":"D1-D3"}, ...],
    "defaultDimensions": {"frontend": [...], ...}
  }
}
```

### PUT 保存语义

```
PUT /capability-standards/{role_key}
body: {
  "dimensions": ["code_quality", ...],   // 可更新维度集（一般不变）
  "standards": {"E3": {"code_quality": 85}, ...},  // 全部职级阈值
  "skillGroupId": "skg-seed-java" | null
}
```
- 更新 capability_roles.dimensions / skill_group_id
- 对 standards 逐职级 upsert（存在则更新 thresholds，不存在则插入）
- 返回更新后的完整角色标准

## 4. 前端设计

### 4.1 types.ts 增加

```typescript
export interface CapabilityRoleInfo {
  roleKey: Role;
  roleName: string;
  dimensions: string[];
  skillGroupId?: string;
  standards: Record<Level, Record<string, number>>;
}
export interface CapabilityMeta {
  dimensionLabels: Record<string, string>;
  allLevels: Level[];
  levelGroups: { prefix: string; label: string; range: string }[];
  defaultDimensions: Record<string, string[]>;
}
```

### 4.2 api.ts 增加（USE_MOCK 双实现）

```typescript
getCapabilityMeta: () => USE_MOCK ? mockDelay(buildCapabilityMeta()) : fetchAPI<CapabilityMeta>('/capability-standards/meta'),
getCapabilityStandards: () => USE_MOCK ? mockDelay({ roles: buildCapabilityRoles(), meta: buildCapabilityMeta() }) : fetchAPI<{ roles: CapabilityRoleInfo[]; meta: CapabilityMeta }>('/capability-standards'),
saveCapabilityRole: (roleKey: string, body) => USE_MOCK ? mockDelay({...}) : fetchAPI(`/capability-standards/${roleKey}`, { method: 'PUT', body: JSON.stringify(body) }),
resetCapabilityStandards: () => USE_MOCK ? mockDelay(true) : fetchAPI('/capability-standards/reset', { method: 'POST' }),
```

mock 实现从现有 `roleConfigs/roleStandards/getRoleStandard` 构建（保留原 mock-data 函数，不删）。

### 4.3 页面改造（capability-standards/page.tsx）

- 页面加载：`useEffect` 调 `getCapabilityMeta()` + `getCapabilityStandards()` → 填充 state（代替从 mock-data import 静态值）
- 保存按钮：收集当前 `standards` + `dimensions` + 可选 `skillGroupId` → `saveCapabilityRole(role, ...)` → toast 成功
- 重置按钮：先本地重置（现状），可选调 `resetCapabilityStandards` 全局重置（或保留局部 reset 语义：重置当前角色为默认值 → 调 `GET` 重新拉取该角色默认）
- 「关联 Skill 组」选择器（新增）：当前角色下方显示 Skill Group 下拉（数据来自 `getSkillGroups`），保存时一并提交——这是与"规则即资产"打通的关键 UI
- 保持现有矩阵表/雷达预览 UI 不变

### 4.4 细节

- 页面数据加载失败（后端未起/mock 模式）时用 mock 兜底，不白屏
- 保存后本地 state 同步更新 + 刷新最近保存时间显示
- `LEVEL_GROUPS` 从 meta 获取（后端定义：D=稀缺高阶 D1-D3、E=资深 E1-E3、F=中级 F1-F3、G=初级 G1-G3）

## 5. 与 Skill 模块衔接

- `capability_roles.skill_group_id` 外键关联 `skill_groups.id`
- GET 单角色时返回 `skillGroupId` + `skillGroupName`（join 查询）
- 前端「关联 Skill 组」下拉用现有 `api.getSkillGroups()`
- 后续可扩展：能力评估时按角色取 Skill Group 规则注入（复用 analyzer 的 `_load_group_rules`）
