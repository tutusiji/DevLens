# 任务：合并两套配置盘点实现（Env Inventory + Config Scan）

## 背景

DevLens 项目中存在**两套并行的「项目环境配置盘点」实现**，均已在 main.py 注册、各自有独立表/路由/seed，功能互补但代码重复：

1. **Env Inventory**（`env_inventory_*` 命名，推荐保留为主）：
   - `backend/app/env_scanner.py`（正则扫描引擎）
   - `backend/app/routers/env_inventory.py`
   - 表：`env_inventory_scans` / `env_inventory_entries`
   - API：`GET /projects/{pid}/env-inventory`、`.../summary`、`POST .../scan`、`.../scans`、`.../scans/{scan_id}`
   - 前端页面：`frontend/app/projects/[id]/env/page.tsx` + 项目详情页 tab 入口
   - 优势：**增量 diff 强**（added/changed/removed + previous_value）、环境归属判定（dev/test/prod/gray/common）、工具类型细（database/redis/nacos/mq/kafka/es/oss/gateway/third_party/other）、前端完整

2. **Config Scan**（`config_*` 命名，解析器强）：
   - `backend/app/config_scanner.py`（**真 YAML 解析器** pyyaml + docker-compose + nginx 专门解析）
   - `backend/app/routers/config_scan.py`
   - 表：`config_scans` / `config_items`
   - API：`GET /projects/{pid}/config-inventory`、`POST .../config-scans`、`GET .../config-scans`
   - 优势：**解析深度强**——结构化拆解 host/port/username/password_masked/database 独立字段、fingerprint 指纹去重、parse_yaml/parse_docker_compose/parse_nginx 专用解析器

用户决定：**两套都要，合并为一个完整模块**（Env 和 config 信息都是需要的）。

## 合并方案

**统一为一个「环境配置盘点」模块，以 Env Inventory 为主骨架（保留其表/路由/前端），吸收 Config Scan 的解析器能力：**

### 1. 解析层整合（核心）
把 `config_scanner.py` 的解析器能力合并进 `env_scanner.py`：
- 引入 pyyaml 解析：`parse_yaml`（扁平化 a.b.c: value）+ `parse_docker_compose`（提取 service 的 environment/image）+ nginx proxy_pass 解析
- 结构化提取：URL 连接串拆解（jdbc/mysql/postgresql/redis:// 等 → host/port/username/password/database）
- Spring 键路径模式：`spring.datasource.url` / `spring.redis.host` / `spring.cloud.nacos.server-addr` / `spring.kafka.bootstrap-servers` / `spring.elasticsearch.uris`
- 通用键名模式：`*_DB_HOST` / `REDIS_HOST` / `NACOS_SERVER_ADDR` / `DATABASE_URL` / `KAFKA_BOOTSTRAP_SERVERS`
- 组合策略：同 source_file + env + host:port + tool_type 的 username/password 从邻近键合并为一条
- 指纹去重：fingerprint（tool+env+host+port+db+source_file 哈希）
- 密码脱敏：`mask_password`（首字符+星号+末字符，长度>8 追加 (len=N)）

### 2. 数据层（env_inventory_entries 表增加结构化字段）
在 `env_inventory_entries` 表追加列（保留现有 diff 字段 status/previous_value/first_seen_at/file_mtime）：
- `host VARCHAR` / `port VARCHAR` / `username VARCHAR` / `database VARCHAR`
- `fingerprint VARCHAR`（去重指纹）
- `detail JSON`（附加信息：namespace/group/服务名等）
- 现有 `key`/`value` 字段保留（value 仍存脱敏值）

注意：**表已存在**（create_all 不会加列），需要 migration 逻辑（参考 main.py 里 ensure_migrate 的 ALTER TABLE 模式：`inspect` 列名不存在则 ALTER TABLE ADD COLUMN）。

### 3. API 层（统一路由，删除 config_scan）
- **删除**：`backend/app/config_scanner.py`、`backend/app/routers/config_scan.py`
- **删除**：models.py 中 ConfigScan/ConfigItem 两个类、schemas.py 中 ConfigScanM/ConfigItemM/ConfigInventoryM 等
- **删除**：seed.py 中 seed_config_inventory（如有）
- **保留**：pyyaml 依赖（backend/pyproject.toml 已加，保留）
- main.py 中移除 config_scan 注册
- Env Inventory 的 API 维持现有路径 `/env-inventory*`（前端已接），响应中把结构化字段（host/port/username/database/fingerprint）暴露出来

### 4. 前端增强
- `frontend/lib/types.ts`：EnvInventoryEntry 增加 host/port/username/database/fingerprint/detail 字段
- `frontend/app/projects/[id]/env/page.tsx`：条目展示增加 host:port / 账号 / 库名 列（有值才显示）
- mock 数据同步补充

### 5. 回归验证
- `pnpm build` 通过
- 后端导入 `from app.main import app` 无错
- 对真实仓库（如 /tmp/devlens-repos/Sa-Token 或 /home/tutuos/CodeLab/calendar-task-manager）跑 full + incremental 扫描，验证：
  - YAML 结构化条目出现（host/port/username/database 有值）
  - 增量 diff 仍正确（无改动 → 全 unchanged）
  - 密码全部脱敏
- 原 Skill 模块 / 项目详情页其他 tab 不受影响
