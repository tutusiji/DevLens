# 🧱 二、每一层怎么讲（核心讲解话术）

---

## ① Data Source（数据源层）

👉 输入世界

- GitHub Repo

- Commit / PR / Issue / Review

一句话：

👉 **“所有分析从真实开发行为出发”**

---

## ② Cognition Layer（数据认知层）

👉 数据 → 机器可理解

### 做三件事：

1. 结构化（commit / PR）

2. 向量化（代码 embedding）

3. 语义检索（RAG）

---

👉 技术：

- Parser（代码/日志）

- Embedding

- 向量数据库（Chroma / Weaviate）

---

一句话：

👉 **“把代码世界转成AI可以理解的语义空间”**

---

## ③ AI Agent 层（🔥核心）

👉 你的最大差异点在这里

---

### Agent 设计：

#### 🧠 Code Agent

- 分析代码结构

- 模块划分

- 技术栈识别

---

#### 👥 Team Agent

- 分析协作行为

- PR / Review / Issue

---

#### 🧑 People Agent

- 建模开发者能力

- 识别角色（架构者 / 维护者）

---

#### 📊 Insight Agent（中枢）

- 汇总所有Agent结果

- 做推理 & 结论输出

---

👉 核心一句话：

👉 **“Agent不是调用，而是持续认知执行单元”**

---

## ④ Modeling Layer（能力建模层）

👉 把分析结果变成“结构化能力”

---

### 三大模型：

#### 🧠 People Model

- depth / breadth / impact

- role

---

#### 👥 Team Model

- bus factor

- ownership

- 结构合理性

---

#### 🧩 Project Model

- 架构质量

- 技术复杂度

- 可维护性

---

👉 这一层是你的**护城河**

---

## ⑤ Insight Layer（决策层）

👉 真正卖钱的地方

输出：

- Team Score

- 风险识别

- 建议

---

👉 示例：

```
⚠️ 单点依赖风险
⚠️ 核心模块集中
✅ 协作良好
```

---

一句话：

👉 **“从数据 → 决策”**

---

## ⑥ UI / API 层

👉 展示 & 商业化

- Dashboard

- PDF报告

- API（未来）

# ⚙️ 三、技术落地架构（工程视角）

---

## 🔧 后端服务拆分（建议）

```text
backend/
├── ingestion-service     # Git数据抓取
├── embedding-service     # 向量生成
├── agent-service         # Agent执行（核心）
├── modeling-service      # 能力计算
├── insight-service       # 报告生成
└── api-gateway
```

---

## 🧠 Agent实现方式（简单版）

每个Agent =

```python
class Agent:
    def collect_data()
    def analyze()
    def output()
```

---

👉 MVP可以：

- 不做复杂multi-agent

- 用简单pipeline模拟

---
