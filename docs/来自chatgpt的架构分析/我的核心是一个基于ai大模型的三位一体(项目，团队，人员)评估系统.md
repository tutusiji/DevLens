# 一、先说清核心：你这个系统到底在解决什么问题？

一句话版本👇  
👉 **把 GitHub 仓库 → 自动转化为“组织能力画像”**

不是做文档，而是做：

- 项目质量评估（代码 + 架构 +活跃度）

- 团队协作评估（PR、Review、沟通模式）

- 人员能力评估（贡献结构、技术深度）

# 二、三位一体 MVP 架构（最小但完整）

## 1️⃣ 数据输入层（第1周搞定）

支持：

- GitHub Repo URL

- 自动拉取：
  
  - commits
  
  - PR / review
  
  - issues
  
  - contributor

👉 技术：

- GitHub API

- 简单缓存（SQLite / Redis）

---

## 2️⃣ AI分析核心（第2周重点）

这里是你产品的灵魂，分三块：

---

### 🧩 项目维度（Project Intelligence）

分析内容：

- 架构模块划分（LLM总结）

- 技术栈识别

- 代码复杂度（简单规则即可）

- 文档完整度

👉 输出示例：

```
项目评分：7.8 / 10
风险点：
- 模块耦合较高
- 测试覆盖不足
```

---

### 👥 团队维度（Team Intelligence）

分析内容：

- PR响应时间

- Code Review覆盖率

- Issue处理效率

- 协作集中度（是否“核心开发者垄断”）

👉 输出：

```
团队健康度：中等
问题：
- Review集中在2人
- Issue backlog较大
```

---

### 🧠 人员维度（People Intelligence）

分析内容：

- 每人贡献结构（代码/设计/修复）

- 技术深度（文件类型 + 模块）

- 活跃度变化趋势

👉 输出：

```
张三：
- 核心模块贡献者
- 偏后端架构
- 代码复杂度高
```

---

## 3️⃣ 向量 + RAG 层（第2周同步做）

👉 是的，你这个项目**必须用向量数据库**

原因：

- Repo 很大（token爆炸）

- 需要语义检索（找相关代码/上下文）

- 用于生成分析报告

---

### 推荐技术栈（轻量MVP版）

| 层         | 技术                     |
| --------- | ---------------------- |
| Embedding | OpenAI / BGE           |
| 向量库       | Chroma（最简单）            |
| 检索        | LangChain / LlamaIndex |
| Chunk策略   | 按文件 / 函数               |

---

👉 MVP原则：

- 不做复杂索引

- 不做代码图谱

- 先能“查 + 总结”

---

## 4️⃣ 报告生成层（第3周）

核心功能：

👉 一键生成：

- 项目评估报告

- 团队健康报告

- 人员能力画像

👉 技术：

- LLM Prompt 模板（非常关键）

- JSON结构化输出

---

## 5️⃣ 可视化（第4周）

简单就好：

- Radar 图（项目/团队/个人）

- 贡献柱状图

- 活跃趋势

👉 技术：

- 前端：Next.js + ECharts

- 或直接 Streamlit（更快）

# 三、MVP功能清单（必须砍到最小）

只做这 5 件事👇

1. 输入 GitHub Repo URL

2. 自动抓数据

3. 生成三类评分：
   
   - 项目
   
   - 团队
   
   - 人员

4. 输出一份 AI 报告

5. 一个简单可视化页面

👉 **不要做：**

- 登录系统

- 多项目管理

- 权限控制

- 高级图谱
