# 👉 **Team = Σ（People Capability） + 结构系数**

也就是：

```text
团队能力 = 成员能力总和 × 结构合理性 × 协作放大系数
```

# 二、三层能力模型（可直接做MVP）

## 1️⃣ 人员能力建模（People Capability）

从 Git 推导👇

### 你可以提取的信号：

#### 🧠 技术深度

- 修改文件复杂度（核心模块 vs 边缘模块）

- 代码类型：
  
  - 架构代码（core）
  
  - 业务代码
  
  - 修复/patch

---

#### ⚙️ 技术广度

- 涉及语言数量

- 涉及模块数量

---

#### 🔥 贡献强度

- commit 数

- LOC（可弱化）

- 活跃时间跨度

---

#### 🧩 角色倾向（这是亮点）

通过行为推断：

| 行为       | 角色  |
| -------- | --- |
| 写核心模块    | 架构者 |
| 高频修bug   | 维护者 |
| 高频review | 审核者 |
| 写文档      | 支撑者 |

---

👉 输出结构（MVP就用这个）：

```json
{
  "user": "alice",
  "depth": 0.8,
  "breadth": 0.6,
  "impact": 0.9,
  "role": "architect"
}
```

---

## 2️⃣ 团队能力合成（Team Synthesis）

关键不是平均，而是👇

---

### 🧮 能力叠加（基础分）

```text
Team_Base = Σ (个人能力 × 权重)
```

---

### ⚠️ 结构惩罚（非常关键）

#### ❌ 单点依赖（Bus Factor）

- 核心模块只被1人控制

👉 惩罚：

```text
Penalty = 高
```

---

#### ❌ 能力分布不均

- 1个大神 + 一堆低贡献者

---

#### ❌ 模块无人负责

---

### ✅ 加分项

#### ✔ 角色完整性

团队是否有：

- 架构者

- 实现者

- 审核者

- 维护者

👉 没有某个角色 → 扣分

---

### 👉 最终公式（MVP版）

```text
Team Score =
  Σ(个人能力) 
  × 结构系数（0.6 ~ 1.2）
  × 协作系数（0.7 ~ 1.1）
```

---

## 3️⃣ 协作放大系数（Collaboration Multiplier）

这个才是你“锦上添花”的部分👇

### 指标：

- PR Review率

- Review参与人数

- Issue互动深度

- 是否有讨论（不是直接merge）

---

👉 示例：

```text
协作差 → 0.7
协作正常 → 1.0
协作优秀 → 1.1
```

---

# 三、MVP实现方式（务实版本）

你不需要一开始搞复杂AI👇

---

## Step 1：规则 + 简单统计（第2周能完成）

用规则先做：

- depth = 是否触达核心文件

- breadth = 文件数量

- impact = commit权重

---

## Step 2：用 LLM 做“角色识别”

Prompt：

```text
根据以下贡献记录，判断该开发者角色：
- commits: ...
- files: ...
- PR行为: ...

输出：
role + 理由
```

---

## Step 3：团队结构分析（关键）

用代码直接算：

- bus factor

- 模块 ownership

- 贡献分布 Gini 系数（🔥推荐）

---

# 四、你这个方向最牛的点（一定要打）

## 🔥 1. 不是“谁写了多少代码”

👉 而是：

- 谁掌握核心能力

- 团队是否健康

---

## 🔥 2. 可以识别“伪团队”

例如：

```text
一个repo：
- 90%代码来自1人
- 其他人几乎无贡献
```

👉 你可以直接输出：

```text
⚠️ 该团队存在明显单点依赖风险
```

---

## 🔥 3. 可以识别“高质量团队”

例如：

- 多人参与核心模块

- Review活跃

- 角色分工清晰
